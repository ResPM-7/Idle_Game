# 유닛 전투 행동 사용 안내

## 부모·자식 구조

```text
Unit_Base_Test (기존 전투 프리팹의 공통 유닛)
  ├─ UnitCombatController (행동 선택·대상 기억)
  │    └─ UnitCombatAction (추상 부모)
  │         ├─ MeleeCombatAction (근접 자식)
  │         ├─ RangedCombatAction (원거리 자식)
  │         └─ HealCombatAction (회복 자식)
  └─ UnitStatusEffects (버프·빙결 타이머)
```

유닛 전체를 종류별 MonoBehaviour 자식으로 교체하지 않고, 전투 행동을 상속으로 분리했습니다. 기존 Unit_Base_Test와 데이터 참조는 유지합니다. 새 행동 클래스는 일반 C# 클래스이므로 인스펙터에서 컴포넌트로 붙이지 않습니다. 공유 행동에는 유닛별 상태를 저장하지 않으며, 대상과 선택 상태는 유닛마다 한 번 만든 선택기에 보관합니다.

## 데이터 설정

| 설정 | 선택되는 동작 |
|---|---|
| Can Melee 켜기 | 적에게 직접 피해, Attack Range 사용 |
| Can Ranged 켜기 | 적에게 Projectile Pool Name 투사체 발사 |
| Can Heal 켜기 | 체력이 부족한 아군에게 Heal Projectile Pool Name 투사체 발사, Heal Range 사용 |
| 근접·원거리 모두 켜기 | 기존처럼 근접 우선 |
| 회복과 공격 함께 켜기 | 회복할 아군 우선, 없으면 적 공격 |
| 회복만 켜기 | 기존 호환 규칙대로 회복할 아군이 없으면 원거리 공격 |
| 모두 끄기 | 탐색·공격하지 않음 |

회복 전용 유닛도 적 공격용 Projectile Pool Name을 연결해야 합니다. 순수 회복만 하는 규칙으로 바꾸려면 UnitCombatController.Configure의 힐러 공격 대체 정책을 변경하세요. 데이터는 Init 시 역할을 반영합니다. 실행 중 역할 플래그를 직접 수정했다면 Combat.Configure(unit)을 호출해 다시 선택하도록 해야 합니다.

신규 행동은 UnitCombatAction을 상속하여 대상 조건·사거리·실행을 재정의하고, 선택기의 Configure/FindTarget에 선택 규칙을 추가합니다. 상태 클래스에서 종류별 분기를 추가할 필요가 없습니다.

## 변경된 탐색 기준

등록된 활성 전투 유닛의 루트 위치를 기준으로 Search Range 안의 가장 가까운 대상을 찾습니다. 물리 콜라이더 표면이 반경에 걸치는지를 검사하던 이전 방식과 경계 판정이 다릅니다. 큰 보스 등은 루트 위치와 탐색 반경을 확인하세요. 루트의 Collider2D가 활성 상태이고 Rigidbody2D가 시뮬레이션 중이어야 대상이 됩니다.

자기 회복을 허용하는 기존 동작을 유지합니다. 풀로 반환되면 등록을 해제하고, 같은 객체가 새 유닛으로 재생성되면 생성 회차를 비교해 이전 타깃을 무효화합니다. 직접 활성화만 하기보다 기존 팩토리와 Init을 사용하세요.

## GC 할당을 줄인 부분과 한계

- 물리 검색 결과 배열 생성 제거: 등록 목록을 인덱스로 순회합니다.
- 매 이동 프레임의 타깃 GetComponent 제거: 선택할 때 타깃 유닛 참조와 생성 회차를 기억합니다.
- 거리 비교에 제곱 거리를 사용합니다.
- 매 투사체·전투 유닛 생성의 캡처 람다 제거: 값 형식 문맥과 보관된 대리자를 사용합니다.
- 버프·빙결 코루틴과 WaitForSeconds 제거: 숫자 타이머로 갱신합니다.
- 공격 애니메이션에서 열거형 ToString 호출 제거: 상수 키를 사용합니다.

최초 객체 생성, 풀이 부족한 경우의 확장, 유닛 등록 목록 용량(초기 256개)을 넘는 경우의 확장, 외부 UI·소리·이벤트·애니메이터 내부 처리는 할당이 발생할 수 있습니다. 게임 전체 GC 0을 보장하지 않습니다. 대상 탐색은 탐색 유닛당 활성 유닛 수에 비례하므로 대규모 전투에서는 CPU 비용을 측정하고 공간 분할을 검토하세요.

## 버프 규칙

최종 공격력은 CurrentDamage의 기본 저장값에 일시 버프 배율을 곱해 읽습니다. 기존 강화 코드에서 CurrentDamage에 기본+강화 값을 대입하면 버프를 덮어쓰지 않습니다. 같은 버프/빙결을 다시 적용하면 최신 배율·지속 시간으로 갱신합니다. 중첩 배율은 지원하지 않습니다. 반환·비활성화 시 효과가 초기화됩니다.

## 검증 방법

재생을 중지하고 **도구 → 검증 → 유닛 전투 행동 검사**를 실행합니다. 임시 씬에서 역할·회복 우선순위·타깃 재생성·강화와 버프를 검사하고 준비 이후 1,000회 탐색·거리 판정·타이머의 관리 메모리 할당을 측정합니다. 이는 실제 전투의 공격·투사체·UI 전체 측정을 대신하지 않습니다.

실제 플레이에서는 근접·궁수·사제를 함께 배치해 공격/회복을 확인하고, 타깃 사망 직후 재생성, 버프 중 강화, 재시작을 확인하세요. 프로파일러의 CPU 사용량과 GC Alloc을 준비 이후 구간에서 비교하세요. 풀 크기를 충분히 확보해 최초 생성 비용을 반복 실행 비용과 구분해야 합니다.
